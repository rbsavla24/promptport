# Changelog

Full user guide: see the README at the root of this repository.

- **v4.0.0 — Magic Port (in development):** full bot migration (prompt + configurations) between Ringg and Rezolv. Adds a third export CTA ("Magic Port") that downloads a complete bot as a ZIP, and an import option that writes it into a destination bot. Migrates all 6 data points — prompt, custom variables, language/voice, custom analysis (prompt + keys), tools (per-phase cURLs), and event subscriptions — with correct cross-platform mapping (incl. Integer→Number). Fail-safes: (1) each item is retried up to 3 times before moving on; (2) the import is gated behind a required consent checkbox, since it OVERWRITES the destination bot; (3) if anything fails, the results screen lists exactly what was not imported and the Close button stays disabled until the user acknowledges it. A backup of the destination's prompt fields is taken before importing. v3.2.4 source is preserved as a frozen replica (`extension-v3.2.4-backup/`).
  - **Re-audit fix (2026-10-30, live Ringg capture):** Ringg's per-phase tool arrays (`pre/on/post_call_tools`) mix tool types — a phase can hold a CALLBACK_SCHEDULE_TOOL or widget tool next to real API tools. The exporter now keeps **only API (cURL) tools** and no longer emits a non-API tool as a broken empty API tool. Non-API tools (callback-schedule, calendar/DOM/form/quick-reply widgets, WhatsApp tools) are recorded as "won't be migrated (out of scope)" and shown on both the import-confirm screen and the results report, instead of being silently dropped. (`additional_languages` is intentionally not captured — scope is primary + secondary language only.)
  - **Rezolv tool import wired to the real UI (2026-10-31, live-verified on QA):** the "+ API" form's parameter rows are added via the real **Add Row → Static Row / Variable Row / JQ Row** menu. **Variable** line items now bind properly through the row's **"Search variable…"** picker (selecting `custom_args.<name>`) instead of being written as a placeholder and flagged. **Body** is handled as line-item rows (it is not a JSON editor). A `dynamic` item (no Rezolv row type) or a variable the picker doesn't list is clearly flagged for manual review rather than written wrong. Verified field selectors: Name (snake_case helper), Method (defaults to Post), `api_url`, and the `button[role=tab]` sub-tabs.
  - **Import hardening (2026-10-30):** the Rezolv tool-form field finders (Name / URL / Method) now fall back to specific, label-based lookups when the primary placeholder/helper cues are absent, so a minor UI change doesn't strand them. Variable tool line-items (headers/query/path) are written as a clear `{{variable}}` placeholder instead of a raw `custom_args.x` literal — consistent with the Body path — and still flagged for manual review, so they can't be mistaken for a completed static value.
  - **Commit cadence (2026-10-30, Raj):** the import now clicks the overall/global Save after EVERY section's own section-Save (committing the agent section-by-section), instead of a single global Save at the very end. After each global commit it re-checks for a login bounce and stops rather than saving into the void; the results report shows the commit count.
  - **Radix interaction fixes (2026-10-31, live-verified on a QA bot):** three live defects all traced to the same two causes — React/Radix controls ignore a synthetic `.click()`, and `Escape` is destructive.
    - *Phase + sub-tab routing.* Phase tabs (Pre Call / On call / Post Call) and the "+ API" sub-tabs (Headers / Path / Query / Body / Response / Settings) are Radix triggers that switch on the pointer sequence, not `.click()`. Rows were therefore all landing in the default Headers panel, and a pre-call tool was being written into On Call. Tab selection now escalates to a full pointer sequence and is confirmed via `aria-selected` before the panel is trusted; the panel itself is resolved through `aria-controls` (with the modal open the document holds nine tabpanels, so "last visible tabpanel" picked the wrong one).
    - *Split parameter rows.* A duplicate dispatch in the row-type menu inserted two rows per item, so the Key landed in one row and the variable in the next and the API could not be saved. The option is now dispatched once, the new row is identified by **diffing** the panel's inputs rather than counting from the end (Body owns a pre-existing "Content type" input, and a Variable Row contributes two inputs), and the picker is scoped to that row.
    - *Event subscriptions.* The events menu stays open across option clicks and the trigger **toggles** it, so re-opening per item was closing it on every other press — only part of the selection landed. Worse, the menu was being closed with `Escape`, which bubbles to the surrounding Radix layer: on the Create Subscription dialog that dismissed the whole dialog so **Create was never pressed**, and in the inline "+ API" editor it removed the editor outright, discarding the tool in progress and silently failing every row after it. The menu is now opened once and every option clicked in sequence, and menus are dismissed with a new `dismissMenu()` — a pointerdown on a neutral node inside the host, which the menu reads as "outside" (and closes) while the host reads it as "inside" (and survives). `Escape` is no longer used anywhere in the import path.
    - *Tool identity.* Rezolv renders tool names only in `aria-label` ("Edit API `<name>`" / "Delete API `<name>`"), never as visible text, and the existence check was scanning the whole document rather than the selected phase panel — so every tool read as "not present" and was created again on each pass. Existence is now checked by `aria-label` within the selected phase panel, which also makes re-runs idempotent.
    - Verified live end-to-end afterwards: one webhook carrying all three events, and both on-call APIs created exactly once with `Authorization` paired in a single Headers row and `client_loan_id` ↔ `custom_args.client_loan_id` paired in a single Body row.
  - **Full end-to-end run against a live Ringg source (2026-10-31):** exported a real production bot straight from the Ringg API and imported it into a QA bot. Three further defects surfaced and were fixed.
    - *Top-level tab navigation never verified.* `gotoTab()` fired a bare `.click()` on the agent's Radix tab triggers and then waited on a condition written `... || true`, so it reported success unconditionally without ever checking that the tab had switched. A section could run against whatever tab happened to be showing — or find no fields at all and report every item missing. It now escalates to the pointer sequence and confirms `aria-selected`, and each caller fails loudly ("the 'X' tab could not be selected") instead of writing nowhere.
    - *Custom Analysis: the key Type was never selected* (reported by Raj). The Type control is a Radix combobox rendered as `div[role="button"][aria-expanded]`, not an `<input>` carrying its value, and it starts **empty** — the word "Type" on screen is a floating label, not a selection. The finder looked for an input whose value was already a type name, found nothing, and the "it's already String" path set nothing; **Add** stays inert until a type is chosen, so no key was ever created. The trigger is now located within the key row and the type is **always** chosen explicitly, never assumed.
    - *Verification read a list that lags its own backend.* Rezolv commits a key server-side before the rendered list catches up, so verifying against the fresh DOM reported keys "missing" that were in fact present — which also drove the retry loop to re-add them. The form's "Key already added" notice now counts as present, and the final type check re-reads until the list agrees rather than judging on one stale pass.
    - *Custom Analysis System Prompt skipped in silence.* `promptOk` was initialised to `true` and only ever set to `false` inside the branch that runs when a writer hook exists, so whenever the hook was absent the section reported success for a System Prompt it had never written — the prompt simply vanished with no entry in the report. A missing hook, a missing editor and a failed paste are now each a named failure ("System Prompt (analysis) — no prompt writer hook"); only a genuinely empty source prompt is a no-op.
    - *Not covered by this run:* the Prompt tab itself (First Message and Main Prompt). The prompt text does not travel in the config JSON — it travels as the `.md` files inside the Magic Port zip, which `content.js` reads and hands to the import through `ctx.importPrompt`. The harness used for this run drives the modules directly and has no `content.js`, so there was neither prompt text nor a writer hook, and the section correctly reported `prompt writer hook not provided`. That path still needs an end-to-end run with the extension actually installed.
    - Result on the destination: variables 12/12, language/voice ok, both on-call APIs created once with correctly paired rows, one webhook with all three events, and all three analysis keys (`reason`, `ptp_date`, `disposition`) present as `String`/Required. The only reported item is `Pre Call: greetings`, correctly flagged because Rezolv's Pre Call phase accepts no API tools.
  - **Commit cadence, overwrite semantics and prompt coverage (2026-10-31):** closing the gaps left by the end-to-end run.
    - *`final-save` reported a failure that wasn't one.* Only four of the six tabs carry an overall Save — Prompt, Custom Variables, Language and Voice and Custom Analysis. **Tools and Event Subscription have none**, because their items commit as they are added ("Add to Assistance" / "Create Subscription"); verified live by counting visible Save controls per tab. The orchestrator committed after every section regardless, so the last section (events) always left it looking for a Save that does not exist, and every run ended "global Save not found". The commit is now skipped where there is nothing to commit, and `final-save.ok` means *every tab that had a Save was committed*. It previously reported only the **last** commit, so a run whose 2nd and 4th commits failed silently still came back `ok: true` — that is fixed too, and each failed commit is named.
    - *`clickGlobalSave` used a bare `.click()`*, bypassing the pointer sequence every other control had already been moved to. Same latent family as the tab triggers.
    - *A section with nothing to do no longer causes a redundant commit.* An empty section returns before navigating, so the following commit re-saved the previous tab. One commit per tab now.
    - *Overwrite semantics made honest.* The consent checkbox claimed the import "overwrites everything on this bot". It does not: there is no delete logic anywhere, and variables, tools and subscriptions are **added**. Rather than make it destructive, the behaviour is kept additive and now made visible — destination-only variables are collected and reported ("left in place, not in the source"), and the consent copy states plainly that nothing is deleted.
    - *Variables verification* also re-reads past the list's backend lag, as the analysis keys already did.
    - *The prompt section is now covered.* `content.js` does supply `ctx.importPrompt` (which writes the First Message and Main Prompt buckets from the zip through the v3-proven path) and `ctx.pasteTipTap`; what had never been exercised was the orchestration around them. Tests now drive it with a faithful ctx and pin: the writer runs only with the Prompt tab genuinely open, the section is saved **after** writing and before navigating away (an SPA tab switch discards unsaved editor content — reversing the order fails the suite), buckets that did not take are named rather than swallowed, a writer returning nothing is not success, and an unreachable Prompt tab fails without running the writer against the wrong tab.
  - **HTTP method carried across and verified (2026-10-31, reported by Raj):** the "+ API" Method control is a **read-only** `<input>` pre-filled `Post`, sitting inside a `div[role="button"][aria-expanded]`; pressing it opens Post / Get / Put / Patch / Delete in Title case, and the value can be changed **only** through that menu. The import used to drive the dropdown only when the source method differed from POST — trusting the form to default to Post — and never checked the result. A method that failed to take was never reported, so the tool was created looking complete while calling the endpoint with the wrong verb, which is worse than a missing row. The method is now **always** set explicitly and read back; a method that will not take fails that tool, names itself in the report ("method could not be set to PATCH") and is not committed. Reverting the fix creates the tool with the wrong verb and reports nothing — `got 1, want 0`. The mapper side is pinned too: `get`, `PaTcH`, `DELETE`, `put` all normalise correctly and a source with no method defaults to POST. The old mock had Method as a plain writable input pre-set to "Post", which is why "the method was set" was never really under test.
  - **Custom Variables: type set, verified, and pinned to String (2026-10-31, Raj):** the variables Type control is a `div[role="button"][aria-expanded]` trigger beside a **read-only** companion `<input>`; pressing the input opens **String / Date** (those two only). Three problems, all now fixed.
    - *The Date branch never ran at all.* The code tested `d.norm(v.type) === "date"`, but `magicport-dom.js`'s `norm()` only collapses whitespace — it does **not** lowercase (`magicport.js`'s `norm()` does; the two are easy to confuse). `"Date" === "date"` is false, so the branch was dead and a Date variable silently landed as String.
    - *Types were never verified.* `verifyVariables` compared **names only**, and `readRezolvVariableNames` threw away the `[Type]` the chip already carries — so nothing downstream could ever have caught the above. A `readRezolvVariableTypes()` now reads name → type off the chips, the type is set explicitly and read back per variable, and a mismatch names the variable in the report. A chip whose type cannot be read is reported as unknown rather than guessed, so an unreadable chip never masquerades as correct.
    - *Ringg has no type on custom variables*, so on a Rezolv destination they are now **always created as String**, stated explicitly in the mapper rather than relying on a default two layers away. A source that somehow did carry a type is noted once ("source type Date ignored — Rezolv custom variables are created as String") rather than silently dropped.
    - Both fixes are mutation-tested: restoring the case-broken compare puts Date variables back to `got "String", want "Date"`, and a mock that accepts the chosen type then writes String anyway is caught only by the read-back.
  - **Event subscriptions at scale: 0, 1 or many (2026-10-31, Raj):** only the single-webhook case had ever been exercised. Testing 0 and many found three problems, one of them reproduced live.
    - *A lagging list duplicated webhooks.* Rezolv commits a subscription server-side before the list renders it, and lags **more** as rows accumulate. The verify read the stale list, reported "not created", and the retry made a **second row for a URL that was already subscribed**. Live on QA with four hooks: a, b and c landed, then the fourth came back as `duplicate subscription x2`. The attempt now waits for the row to actually appear (`waitFor(countFor(url) >= 1)`) before ending, and re-reads once after a settle before creating — so a retry can no longer duplicate. Reverting it reproduces the failure offline as `got 8, want 4`: every hook duplicated.
    - *The dialog finders searched the whole document.* "The first empty visible text input" is fine with one subscription on screen and a coin-flip with ten — any filter or search box rendered above the dialog would swallow the URL. Both the URL field and the events combobox are now scoped to `[role="dialog"]`. With the mock's decoy search box, the unscoped version types the URL into it and creates an **empty-URL row**.
    - *0 webhooks was not a clean no-op.* The section navigated to the Event Subscription tab (and could fail on a tab it never needed), and reported `created` as the number of rows **on the page** — so a source with no webhooks and two pre-existing subscriptions reported "created: 2". It now returns early, and `created` counts what this run actually created, with `alreadyPresent` for ones already on the destination and `onPage` for the total.
    - Covered by tests for 0, 10, a URL repeated in the source, partial overlap with the destination, and a lagging list.
  - **Tools at scale, and which phases actually exist (2026-10-31, Raj):** verified live on Rezolv QA — **only "On call" accepts API tools**. Pre Call *and* Post Call both render "Coming soon." and carry no "+ API" control, so nothing from either phase can be migrated there at all. (Checked on QA; production may differ.) Four problems found and fixed.
    - *The same lag-driven duplication as the webhooks.* The tools list renders behind its own backend and lags more as rows accumulate, so the verify read a stale panel, reported the tool missing, and the retry added it **again**. The attempt now waits for the row to appear before ending, and re-reads after a settle before adding. Reverting it duplicates almost every tool: `got 9, want 5`.
    - *Skipped tools lost their names.* The report read `"Pre Call: tool"` for every unmigratable tool, because the raw Ringg object carries `tool_name` while the code read `.name` (only `extractToolParts` produces that). Three unmigratable pre-call tools produced three identical useless lines. Each tool is now named.
    - *"Coming soon." was matched against the whole page.* `phaseUnavailable()` read all of `<main>`, so that text appearing anywhere would have declared **every** phase dead. It is now scoped to the selected phase's own panel, with the absence of a "+ API" control as a second signal.
    - *A phase that becomes usable will be used.* The unavailability check is a live DOM read, not a hardcoded list, so when Rezolv ships Pre/Post Call tools they start working without a code change — pinned by a test where Post Call is available and the tool lands there.
    - Covered by tests for: no tools at all, only pre_call, only on_call, several on_call with a lagging list, multiple unmigratable pre-call tools each named, and a usable Post Call phase.
  - **Offline suite rebuilt against the live DOM (2026-10-31):** the previous mocks encoded the wrong DOM and the events mock stubbed out the very function under test, which is why 187 assertions passed while the live run failed. Mocks now model the real shapes — pointerdown-driven Radix tabs, decoy controls sharing sub-tab labels, names only in `aria-label`, Body's pre-existing "Content type" input, a menu that persists across clicks and toggles on its trigger, and `Escape` tearing down the host. Every fix was mutation-tested: reverting it reproduces the exact reported symptom — reverting the Type-control finder, for instance, yields `got []` where two keys were expected, exactly the live failure. The mocks now also model the top-level Radix tab bar, the empty-start Type combobox, and a list that lags its backend. **225 assertions, 0 failing** (events + tools scale coverage).
  - **Deep stress test (2026-10-30):** 187 offline assertions across the engine, DOM primitives and the import orchestrator (adversarial envelopes, circular refs, every type/variable/analysis/webhook shape, credential-leak guard, round-trip, full run-order, REQ-1/REQ-2 verify, retry/auth-stop/phase-unavailable, 3-site host matrix). Hardened `pickAgent` so a malformed capture can't throw and abort an export.

- **v3.2.4 — line breaks on import (both sites):** a line break you type in a .md file now stays a line break (before, two lines like “**Q:** …” and “**A:** …” were joined into one). Exports still re-import as “Nothing to change”.

- **v3.2.3 — safety fix (Ringg):** the background data reader now only ever repeats a page *read* (GET). Before, if the assistant data had last come from a save, it could re-send that save without its content when you exported after a lot of page activity. It also keeps the latest assistant data so names stay correct.

- **v3.2.2 — live-tested on both sites:** exported files no longer contain whitespace-only lines inside list items.

- **v3.2.1:** on Rezolv, lines separated by a single line break (common in Ringg prompts) now arrive as separate paragraphs instead of running together (that editor has no line breaks), and re-importing the same file there reports "Nothing to change". The last import can be undone from the Import tab even after you leave its results screen.

- **v3.0.0 — UI 2.0:** greyscale, Verdana, hand-drawn panel with no product name or logo, equal side-by-side download buttons, sticky actions, site-neutral wording everywhere in the UI, and author links (LinkedIn · GitHub · Figma) that appear after a download, import, undo, backup or Replace all finishes and hide when the next one starts.
